Slice: {slice}

Your one job: make the context index in session-plan.md (below `<!-- gathered -->`) match what the main session needs for this unit, then report. The main session will read the task file first, then the packet in session-context.md; do not leave investigation it still has to redo.

1. Read session-plan.md{task_step}{request_step}.
2. Check the seed with `wdb__lookup` when it is connected, otherwise `{py} tools/find.py ...`. Keep the core small: what will be read or edited in every case. Make an item a candidate (`--cand --when "read if/when ..."`) when it is needed only in some cases. Remove what this unit does not need. Follow the request down to the code that causes each problem (a handler, a flag, a missing call) so the main session starts at the cause, not at the menu that shows it. For a platform-specific problem (mobile, web, touch, keyboard, export), also search the project and export settings (`project.godot`, `export_presets.cfg`) for the feature, e.g. `wdb__lookup action=xref pattern=virtual_keyboard` (xref searches both by default): the cause may be a setting, not a script.
3. Scope to the part a long file needs: `add-doc PATH#Heading`, or `add-doc PATH --lines A-B` / `add-file PATH --lines A-B` for a range (one file may hold several ranges; `rem` the whole-file item first). `wdb__lookup action=doc path=DOC` (no #Heading) lists a doc's headings and paragraph starts with line numbers; `action=xref pattern=TEXT path=FILE` finds lines in data files such as `scripts/data/locale/en.po`.
4. Change the index only with `{py} tools/slice.py adjust ...`. Several ops in one call: `adjust batch --op "rem K4" --op "add-func PATH NAME --why 'edited'" --op "set-condition K5 --when 'read if ...'"` (`adjust --help` lists every op; `--dry-run` first prints every error). `--reason` is optional.
5. Run `{py} tools/slice.py expand --check`. Fix every item it names until it passes.
6. Finish with `{py} tools/slice.py adjust report --text "<2-6 lines: does the door/job fit the task, where the cause of each problem is, what the main session should know first>"`. Add `--halt "<reason>"` only when the slice should not start as opened (wrong door or job, the task is contradictory, or a needed file is missing). The User then decides.

Batch your reads: a turn is one model round, and every tool call you make in parallel in that round counts once. Put independent reads in one round, or in one call: `wdb__lookup reads=[{\"action\":\"names\",\"path\":\"A.gd\"},{\"action\":\"func\",\"path\":\"B.gd\",\"name\":\"f\"},{\"action\":\"doc\",\"path\":\"design/x.md\"}]`. Pass `all=true` when you will need the whole result, so there is no `more` follow-up. When that MCP is not connected, make the same reads as parallel `{py} tools/find.py` and `{py} tools/docs.py` commands. A `doc` without `#Heading` is its outline with line spans; then read `doc path#Heading` or `lines` ranges.

The run stops at {max_turns} rounds as a runaway guard (an error exit, and the main session then gets the plain seed); it is not a budget to ration.
